User guide

Name the skill. Then name a new subject.

Fifteen skills in this folder each carry one technique from the Opus 5.5 builds. You bring the subject. The agent builds a piece you can play, watch, or click through.

Call a skill by name

The skills live in .cursor/skills/ in this project. Each one is marked so the agent does not pick it up on its own. A request like “make something cool” will not load them.

In Cursor chat, write the skill name in the message. Use this shape:

Use the <skill-name> skill.
Subject: <one sentence that is not the reference build>.
<Whatever that skill asks you to supply: photos, a sketch, a title, a place.>

Example: browser-soulslike with a flooded subway, not the snowbound monastery in the reference.

These skills belong to this project. Open this folder in Cursor before you chat. Copying only this HTML file into another repo does not bring the skills with it. Copy .cursor/skills/ too.

Keep the technique. Change the subject.

That is the rule in the variation set. The source video, Top 15 Things built with Claude OPUS 5.5, shows fifteen builds other people posted. The repo keeps each technique and look, and swaps the subject. A camera-lens lab becomes an eye lab. A kart racer becomes a jet-ski racer. A sand film of US history becomes a sand film of the Silk Road.

Do the same thing one step further. The reference is there so the agent can see a working shape. Your message names the new subject. If you want the reference subject itself, say so. Otherwise the skill is written to refuse that default.

A subject is a picture, not a genre

“A game” gives the agent nothing to aim at. “A soulslike in a flooded subway, rest at the ticket booths” can be screenshotted, explained in one sentence, and handed to a friend.

Write the subject before you call the skill. One sentence, plus the props that belong in the thumbnail: the tool in the player’s hands, the year on the sand table, the title on the film card.

Play it, then run the checks

Most of these builds are one HTML file. Browsers block ES modules opened with file://, so serve the folder:

python -m http.server 8000

Then open http://localhost:8000/ and the page the agent just wrote. Turn sound on for films and title sequences.

Each skill ends with checks you can see: drag the control, finish a race, rest at a shrine and watch the enemy return, pull the keystone and watch the structure fall from the physics. Do those. A build that only looks right in a screenshot is not done.

Five skills need something besides a browser tab:

The fifteen

Each skill has three prompts. They do not share a setting. Send one as written, or write a fourth subject that is unlike all three. None of them is the reference build.

interactive-focus-lab

A dark 3D lab. A cutaway instrument on a bench. Drag the focus control and a sharp plane moves through a tabletop diorama.

You supply
The instrument, three distances, and any defects.
Reference
Eye Lab, a lens-lab variation.

A Night street, a camera

Use the interactive-focus-lab skill.
Subject: a camera lens on an optical bench, at night.
Diorama: a neon sign close, a parked car in the middle, a tower far away.
Apertures: f/2, f/5.6, and f/16. Include an exploded view and named textbook values.

B A pond drop, a microscope

Use the interactive-focus-lab skill.
Subject: a compound microscope over a drop of pond water, in daylight.
Diorama inside the drop: a strand of algae close, a water flea in the middle, a grain of silt far.
Show the condenser iris at three openings. A dirty objective veils the silt. A cleaned objective makes it sharp.
Exploded view: eyepiece, objective, stage, mirror. Name the magnification of each objective from a real student microscope.

C A rooftop, a telescope

Use the interactive-focus-lab skill.
Subject: a small refracting telescope on a rooftop at night.
Diorama in the sky: a moon crater close, Saturn in the middle, a radio mast on the horizon far.
The drag control is the drawtube. Show chromatic fringe at the moon's edge, and a filter that removes it.
Exploded view: objective lens, drawtube, eyepiece. Use published focal lengths and name them.

A heavy book is set on the seat. Sliders for book mass and joint friction.

What made those builds travel

The video is a tour of work people had already posted. The repo’s own note is plain: a variation keeps the technique and the look, and changes the subject. The pieces that read in a thumbnail share a few concrete traits.

  • One screenshot explains the whole idea. A cutaway eye on a bench. A sand table with a year in the corner. A race HUD. A sketch lifting off paper.
  • A stranger can open a link and play, or press play on an MP4. Most references are one HTML file on GitHub Pages. Snow Day is the exception, because it needs a server.
  • The trick is something you can do, not a caption. Drag the muscle. Pour one fluid on the other. Pull the pin. Turn the page. Rest, and the enemies return.
  • Sound is part of the piece when the technique has sound: the lyric video, the pattern film, the title sequence, the sand film.
  • The checks in the skill are the same kind of checks the repo used. The README lists the ones the reference builds missed. Those misses are in the skills as things to fix, not as the look to copy.

When a build is up, record ten seconds of the trick and put that next to the link. That clip is what the original posts were: a short look at a finished object, with the subject changed enough that it is yours.

Before you send

  1. Pick one skill from the list above.
  2. Pick one of the three prompts, or write a subject unlike all three.
  3. Add the inputs that skill asks for. Photos, a sketch, Blender, and a vocal track cannot be implied.
  4. Paste the prompt. Wait for a file you can open.
  5. Serve it, play it, and run the checks written in that skill’s SKILL.md.
